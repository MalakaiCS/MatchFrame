# Acceptance results (MVP_SPEC.md §26)

Status meanings: **PASS** — executed in this repository with the cited evidence and it met the expected
result. **PARTIAL** — executed, but only part of the expected result is covered or it was covered only with
the deterministic fake media provider. **FAIL** — executed and did not meet the target. **BLOCKED** — not
executable in this environment (reason given). Nothing is marked PASS without an executed check.

Environment for all runs (2026-10-19): Claude Code cloud container, 4 vCPU, 15 GiB RAM, Docker 29.8.2,
Node 22.22.0, PostgreSQL 16.10, Redis 7.4.6, MinIO (pgsty build 2026-08-04), LiveKit server 1.13.8 /
ingress 1.5.0 / egress 1.14.1, FFmpeg 6.1 (host) / 7.1.1 (image), Chromium 1194 (Playwright 1.56.1).
Media source: `tests/media/fixtures/test-source-720p30.mp4` (generated by `tests/media/gen-fixture.sh`:
testsrc2 motion + timer, white flash and 1 kHz 100 ms beep at every second), pushed with `ffmpeg -re -c copy`
over RTMP (H.264 high 2.5 Mb/s, AAC 128 kb/s, 1280×720 30 fps).

Test suites referenced: `pnpm test` (unit, 59 tests), `pnpm test:db` (integration on real PostgreSQL with
the `bs_app`/`bs_worker` roles, 51 tests incl. real FFmpeg + MinIO), `pnpm test:e2e` (Playwright against the
running stack, 4 specs), and the real-media scripts in `tests/media/` (LiveKit + RTMP receiver).

## A51 and measured capacity

| Configuration (4 vCPU / 15 GiB, all services on one host) | Result |
| --- | --- |
| 1 session, programme only (M0, highlight e2e, audio policy) | Stable; LIVE in 8–14 s; A/V skew in M0 median +79 ms (stdev 138 ms, outliers to ±400 ms — not a strict pass of ≤150 ms) |
| 1 session, programme + clean (smoke) | Works for minutes; egress ≈250 % CPU, ingress ≈105 %, load 15–20; receiver reconnects observed on clean |
| 2 sessions, programme each, 30 min (soak) | Both LIVE throughout (one 70 s control-plane restart during the run did not interrupt egress), but host oversubscribed (load avg 46, max 76), 42/47 receiver reconnects per output, 1,745/1,800 s recorded, marker pairing failed → **FAIL** |

The installation default `MAX_CONCURRENT_PROGRAMMES=2` (outputs) reflects "one session with programme + clean" on
this host, and even that saturates it. The §2.2 target of two simultaneous 720p programmes is **not demonstrated**
here; re-run `tests/media/run-soak.mjs` on a media node with more cores before raising the limit.
